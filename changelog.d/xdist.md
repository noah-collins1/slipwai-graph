MINOR

**A new Python service's gate runs its tests across cores, and a project can turn that off with one line.** `slipwai generate` now writes `"parallelSafe": true` into a new project's `project.json`, and the generated `scripts/verify` reads it each time it runs: where it is the JSON `true`, the gate's `pytest` in `make test` and `make verify` takes `-p xdist -n auto --maxprocesses 4` (`pytest-xdist==3.8.0`, loaded by name so a run with `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` still starts its workers; pinned in every Python service's development tools and in the four committed locks, so the plugin is installed whatever the mark says). The cap of four workers is deliberate: it keeps the machine usable beside the other checks `make -j verify` runs. Anything else — `false`, no key, a file that cannot be read — is the serial run it was; so is every run where `CI`, `GITHUB_ACTIONS` or `GITLAB_CI` is set, because a parallel run can hide a test that depends on another test's leftovers (the two may land on different workers), so CI keeps the serial verdict it gave before this release, and a test that passes locally but fails in CI is the first thing to look for; the adversarial run is serial too, and Python's integration run is never parallel, because its tests share one database; and a person's own `pytest` is unchanged, since the template's `addopts` does not name `-n`. The other backends' test commands are unchanged: the gates page now says, for each backend a project has, what its runner already does — Vitest runs test files in parallel, `go test` runs packages in parallel, Maven's Surefire runs one at a time — and, for a Python service, what the mark does, that a missing mark is serial, and to set it `false` where tests share a file, a port, a database or module-level state. On a small suite the workers cost a fraction of a second, and they pay back once the suite takes several seconds. Every `slipwai` command that reads `project.json` now refuses one that writes a key twice, or a `parallelSafe` that is not a finite JSON value, in one line and before writing anything; `slipwai migrate` says so after its merge when the merge itself left a key twice.

Measured at the demo on a fresh Python starter (87 tests, warm, a 12th Gen Intel Core i5-12400 with 12 cores), medians of three runs, with the mark and without it: `./scripts/verify --test-only` took 1.36 s and 0.99 s; `make verify` took 3.70 s and 3.30 s; `make -j verify` took 2.11 s and 1.72 s. On a starter the workers cost about 0.4 s, which the stamp spares on every run of an unchanged tree.

**Catch-up.** A project made before this release stays serial: `slipwai migrate` carries a project's own `parallelSafe` and never adds one, and `adopt` writes none. To opt in, add the line `"parallelSafe": true,` to the project's `project.json` once, with its comma, right after the `"target"` line, where `generate` writes it (a mark written twice is serial, because the gate cannot tell which copy is meant, and `migrate` names it in its report and in `.slipwai/catch-up.md` when its merge leaves one there: keep one copy; only the JSON `true` turns it on), and run `make verify` once; set it `false` to turn it off again. Every Python service's `pyproject.toml` and `uv.lock` gain `pytest-xdist`, so where a project has a dependency of its own, dev or not, `slipwai migrate` stops on a conflict in `apps/<service>/uv.lock` (the service's path as `project.json` records it): take either side of that file, run `uv lock --project apps/<service>`, `git add` the lock and commit. That is done once by hand, for each service of such a project.
