MINOR

**A new Python service's gate runs its tests across cores, and a project can turn that off with one line.** `slipwai generate` now writes `"parallelSafe": true` into a new project's `project.json`, and the generated `scripts/verify` reads it each time it runs: where it is the JSON `true`, the gate's `pytest` in `make test`, `make verify` and the adversarial run takes `-n auto --maxprocesses 4` (`pytest-xdist==3.8.0`, pinned in every Python service's development tools and in the four committed locks, so the plugin is installed whatever the mark says). The cap of four workers is deliberate: it keeps the machine usable beside the other checks `make -j verify` runs. Anything else — `false`, no key, a file that cannot be read — is the serial run it was; Python's integration run is never parallel, because its tests share one database; and a person's own `pytest` is unchanged, since the template's `addopts` does not name `-n`. The other backends' test commands are unchanged: the gates page now says, for each backend a project has, what its runner already does — Vitest runs test files in parallel, `go test` runs packages in parallel, Maven's Surefire runs one at a time — and, for a Python service, what the mark does, that a missing mark is serial, and to set it `false` where tests share a file, a port, a database or module-level state.

**Catch-up.** A project made before this release stays serial: `slipwai migrate` carries a project's own `parallelSafe` and never adds one, and `adopt` writes none. To opt in, add the line `"parallelSafe": true` to the project's `project.json` once, right after the `"target"` line, where `generate` writes it (a mark written twice is serial, because the gate cannot tell which copy is meant, and only the JSON `true` turns it on), and run `make verify` once; set it `false` to turn it off again. Every Python service's `pyproject.toml` and `uv.lock` gain `pytest-xdist`, so where a project has a dependency of its own, dev or not, `slipwai migrate` stops on a conflict in `apps/<service>/uv.lock` (the service's path as `project.json` records it): take either side of that file, run `uv lock --project apps/<service>`, `git add` the lock and commit. That is done once by hand, for each service of such a project.
