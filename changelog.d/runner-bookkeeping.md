MINOR

**A `/cruise` run reads what it has already read once, not again before every iteration, and a decision entry can now say which slices it binds.** The runner's own bookkeeping grew with the run: at iteration 50 it read the whole log up to three times, the whole raw stream to find one iteration's lines, every file under `specs/` to fingerprint it, every control before and after, and hashed every tracked file for the code index. It now keeps what it read and re-reads a file only where the file no longer reads as it did.

- **The log** is read whole once per runner process; while it is exactly as the runner left it (size, times and identity), the next iteration's number and the stuck window come from memory. A log another hand touched is read whole again, as before. **The stream** is read from the byte the iteration's marker was written at, where the bytes there are that marker line; otherwise whole, as before.
- **Each log entry may carry a `bookkeeping` object**, optional and absent from entries written earlier: `log_bytes`, the bytes the runner read from the log since its previous entry, and `stream_bytes`, the bytes it read from the stream for this entry (absent where the harness keeps no stream). Nothing reads it back but a person, and a log written before this release is read exactly as it was.
- **The fingerprint** is now the path and content of each file under `specs/`, each read once while its size, modification time, change time and identity stand; it keeps its name and its 16 hex characters, and its value for a given tree is not the one earlier code gave. What it cannot see: a file under `specs/` whose bytes changed while its size, modification time, change time and identity all read as before — a clock set back, a filesystem that keeps no such times — is not seen by that runner process; a commit, any other change, a person's message or a new runner process sees it.
- **The controls** (`scripts/`, `tools/`, the Makefile, CI, hook files) are compared by content as before, each read once while all four of those facts stand; where a platform reports fewer, every control is hashed every time. What it cannot see: a control whose bytes were changed while its size, modification time, change time and identity all read as before — a clock set back — is not seen by that runner process; a new runner process hashes everything.
- **The runner's check before an iteration** (`health()` in `scripts/agents/code_index.py`) compares only what changed since the last whole comparison, on any branch and outside CI, from the same record the narrowed `check-codegraph` keeps in `.codegraph/gate-memory.json`; it says how many files it hashed of how many, still runs SQLite's integrity check, and renews the record when it ends current. What D49's sentence on a narrowed comparison says holds for it too: a file whose bytes changed while its size, modification time, change time and identity all read as before is not seen by it; the next whole comparison sees it — `make verify` on the trunk or any branch not named `slice/<id>`, CI, or any check after `.codegraph/gate-memory.json` is deleted. Deleting that file makes the next comparison whole. The gate itself is unchanged: on the trunk, on any other branch and in CI it compares every file and runs the integrity check, as before.
- **`Scope:`.** The entry `/cruise` writes gains a line directly after the Stage line, `- **Scope:** <slice ids, comma-separated> | global`: the slices whose later decisions must agree with it, or `global` for a feature-level decision or one the writer is unsure of. The cruise command, a newly seeded owner brief and the `drive-skipper` and `drive-bosun` briefs show and ask for it, and tell a delegate to read a slice's standing entries through `python3 scripts/check-decisions.py --scope <slice-id>` (the whole log where no slice is named). `make check-decisions` accepts an entry without the line and refuses a malformed one, naming it.

The pages that said only the gate narrows — the verification page, the code-index extension's block in `AGENTS.md`, `docs/cruise.md` and the `code_index.py` docstring — now say the runner's check does as well.

**Catch-up.** Nothing is asked of an existing log: an entry without a `Scope:` line is carried as global, and one without a `bookkeeping` object is read as it always was. A refresh never rewrites a project's own owner brief; `slipwai migrate` merges the new entry shape beside what the project wrote there, and where a merge leaves the entry example without the `Scope:` line, add it by hand. A run already going when the runner is replaced is given up to `stuck_after − 1` more iterations before the stuck detector parks it, once, because the fingerprint's value changed. The first code-index check after the upgrade compares every tracked file, since the record it reads is keyed on the script that wrote it.
