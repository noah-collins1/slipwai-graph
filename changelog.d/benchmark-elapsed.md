MINOR

**`make benchmark` now says how long a slice took from ready to accepted, and where the time went while nobody was working on it, instead of passing off the sum of its stage brackets as the slice's wall time.** The old `wall` figure was the brackets added up, so a slice that sat a day waiting for a dependency, a review or a merge read the same as one that did not, and a feature's slices, whose brackets overlap, summed to more time than had passed, and the feature heading printed that summed stage time as if it were elapsed. The overview now carries three figures under three names: **elapsed**, which runs from the slice's ready commit to its accepted one and is read from git; **stage time**, which adds up the brackets and is what `wall` was; and a waiting table that splits elapsed by cause — dependency, worker, review, integration, and what no record accounts for — beside the work a refused demo sent back and the slice's cost. Each request a delegate made is now charged to one slice by following the spawn chain the harness records up to the `drive-slice` delegate whose description names the slice, a cut-off entry's stage time ends at the latest line of the requests attributed to it (its recorded end stands where that line precedes its start), every figure says where it was read, and a figure nothing could read says `unknown` with the reason and never a bare `0`. Decision health reads `unknown` until a decision carries a tier. The ladder gains a `gate` stage, the full gate run after a slice's merge, which the host brackets as the slice's own, and `/drive` and `/cruise` ask each `drive-slice` delegate to be described as `drive-slice <id>` so its requests can be charged to the slice.

**Catch-up.** `slipwai migrate` brings the new `scripts/agents/measures.py` and `scripts/agents/attribution.py`, the changed `scripts/agents/benchmark.py` and the regenerated `commands/drive.md`, `commands/cruise.md` and `commands/benchmark.md`, and nothing else asks anything of the project. In the overview and in `make benchmark`, `wall` → `stage time` (the same figure, except that an entry the next iteration cut off ends at its last transcript line wherever stage time is printed, and `--json`'s `entries` keep the recorded seconds as `recorded_seconds`) and the `rework` column → `re-entered` (the same list of stages re-entered after implementation); in `benchmark.py --json`, `rework` is now an object `{seconds, tokens}`: the stage time and attributed tokens of every entry after a demo whose outcome was `behaviour` or `implementation`, up to the next demo, which is the work a refused demo sent back, and the old list of stage names is under `reentered`, so a script that read `rework` as a list reads `reentered` instead. The new figures sit under new keys: `feature_figures`, `session_totals` and `decision_health` come once per feature, on its own record or, where it has none, on its first slice record, and each record's `read_from` says where every figure was read. The `gate` stage is a new stage name that an `end` takes no signals for: bracket the full gate after a slice's merge with `python3 scripts/agents/benchmark.py start specs/<feature>/slices/<id> gate` and `end` as the regenerated `commands/drive.md` says, and describe each `drive-slice` delegate as `drive-slice <id>`; records written before are read as they are, and a delegate's requests are charged to a slice by following the spawn chain recorded in the harness's sub-agent metadata up to the `drive-slice` that spawned it, whose description names the slice (`drive-slice <id>`, or for descriptions written before the convention, their first word), a request tied to no slice being counted in the feature's shared bucket. Where the transcripts are not on the machine the recorded per-stage tokens stand in, and the cost says so; a figure that brackets in this checkout or at the tip of any local branch, whatever the branch is named, would double-count reads `unknown` (a newer copy on a branch of a record this checkout holds counts too, for the entries the checkout lacks), as it does where git cannot list or read those branches. Elapsed and every waiting cause read `unknown` in a shallow clone, where the history that says when a slice was ready is cut off, and wherever a git command they depend on fails. Review, worker and unattributed read `unknown`, naming the line, where `specs/cruise-log.jsonl` has a line that cannot be read whole; with a readable log, time between and after its iterations counts as worker, and with no log it stays unattributed. Review is read only from a demo a person was at (closed with an `outcome` and no `driver`), never from a park: time the cruise log says a person held the run (`stopped: human` or `parked:`), to the next row or the first bracket begun after it, is part of `unattributed` and is named by the new `--json` key `unattributed_person`, beside `waiting`, whose five keys are unchanged; and each record's `cost` gains `sessions`, the tokens it was charged per session, so that the records and the shared bucket can be checked against a session's total. A feature that shares a session with another splits its shared bucket by the brackets that cover each request. *Merged* is the slice's own merge on the integration branch's first-parent history, never a catch-up merge into the slice. A median wait in decision health says how many entries it was read from, and a review's verdict is the first word of a decision's `Status:` line. Throughout, no record is rewritten, no `project.json` key changes, `make check-benchmark` warns of nothing it did not warn of before, and nothing must be redone.
