# Research: S42-mutmut-mutation

Every statement about mutmut's behaviour below cites the run or the source it was read from. Runs were made on
2026-10-08 in scratch starters generated by this branch's factory (`./slipwai generate … --no-init --no-install
--skip-checks`, worktree at `b9f16ef`) under `/tmp/s42/`: **demo** is the default answer on every axis for the Python
backend (`event-modelling`, `react-vite`, FastAPI, Postgres), **mini** is `--profile standard --frontend none --http
none --event-store memory`. In each, `mutmut==3.8.0` was added to the service's dev group by hand, `uv lock`, `uv sync
--locked`, and the `[tool.mutmut]` table of R2 appended. Machine: 12th Gen Intel i5-12400, `nproc` 12, Linux
7.0.0-31, host Python 3.14.4, uv 0.12.21; the service environment's interpreter is 3.14.4. Source read is the installed
wheel, `.venv/lib/python3.14/site-packages/mutmut/` (named below as `mutmut/…`).

## R1 — Which mutmut (D216)

**Decision:** `mutmut==3.8.0`, exact, in every Python service's `dev` group (`BASE_DEVELOPMENT` in
`src/slipwai/project/languages/python.py`), and therefore in all four committed locks
(`assets/languages/python/locks/uv*.lock`, regenerated by `scripts/regenerate-locks.py`).

**Evidence.** PyPI's JSON (`https://pypi.org/pypi/mutmut/json`, read 2026-10-08): `info.version` 3.8.0, uploaded
2026-09-12; no 4.x exists, so D216's *would reverse if* does not apply. `Requires-Python: >=3.10`; it requires
`click>=8.4.2`, `coverage>=7.3.0`, `libcst>=1.9.0`, `pytest>=6.2.5`, `setproctitle>=1.3.7`, `textual>=1.0.0` (and
`toml` below 3.11) — `mutmut-3.8.0.dist-info/METADATA`. `uv lock` on the demo service added 13 packages (coverage,
libcst 1.9.0, linkify-it-py, markdown-it-py, mdit-py-plugins, mdurl, mutmut, platformdirs, pyyaml, pyyaml-ft, rich,
setproctitle, textual), 458 lock lines; `uv sync --locked` accepted it. `pip-audit` over the exported lock
(`uv export --frozen --no-emit-project --no-hashes`) reports only `urllib3 2.7.0` (three PYSEC-2026 advisories), which
is in the lock before mutmut is added (OpenTelemetry's exporter brings it) — none of the 13 is named.

## R2 — The configuration mutmut 3.8.0 reads, and what the factory writes (AC-S42-1)

`mutmut/configuration.py`, `_config_reader`: `pyproject.toml` in the **working directory**, table `[tool.mutmut]`,
read with `tomllib` on 3.11+ (`toml` below); where the table is absent it falls back to `setup.cfg`'s `[mutmut]`, then
to guessing (`lib`, `src`, the directory's own name). `paths_to_mutate` is **deprecated** in 3.8.0 (a warning; renamed
`source_paths`), and `tests_dir` likewise in favour of `pytest_add_cli_args_test_selection`.

**Decision:** the template `assets/languages/python/app/pyproject.toml` gains, with a comment above each line:

```toml
[tool.mutmut]
source_paths = ["src"]
pytest_add_cli_args_test_selection = ["tests", "--ignore=tests/integration"]
pytest_add_cli_args = ["-p", "no:xdist"]
```

- `source_paths`: mutmut walks every `.py` under `src/` (`utils/file_utils.py`, `walk_source_files`) and names each
  module from its path with the `src.` prefix stripped (`utils/format_utils.py`, `get_mutant_name`).
- The test selection is used for the stats run and the forced-fail run when no test ids are given
  (`runners/harness.py`, `_pytest_args_regular_run`, `list_all_tests`). With `tests/integration` ignored, the Postgres
  starter's run needs no Docker: the demo run ended with 463 *no tests* mutants (both Postgres stores, 369; `main.py`,
  55; `openapi.py`, 27; and 12 in `events.py` and `projections_lifespan.py`) and no failure.
- `pytest_add_cli_args` is appended to every pytest invocation (`execute_pytest`). `-p no:xdist` keeps a parallel run
  from hiding tests from the stats collector.
- Every service writes the same table — the paths are relative to the service, which is the directory mutmut runs in —
  so it lives in the template, not in Python code. Nothing excludes `main.py`, `openapi.py` or the Postgres adapters as
  D213 did for TypeScript: mutmut has no coverage denominator, and a mutant no test reaches is *no tests*, counted and
  never failed (D212 item 2).

## R3 — How a run is shaped, and why the wrapper generates before it runs (D212 item 4, D216, AC-S42-6)

`mutmut run [MUTANT_NAMES…]` (`mutmut/__main__.py`, `_run`): copies `source_paths` and the `also_copy` set (`tests/`,
`pyproject.toml`, `uv.lock`, …) into `mutants/`, **generates the mutants of every file** (`create_mutants`, writing
`mutants/<path>.meta`), collects stats with one run of the selected suite, then filters to the names given by
`key in names or fnmatch(key, name)` and **asserts** a non-empty result (`collect_source_file_mutation_data`:
`assert filtered_mutants, "Filtered for specific mutants, but nothing matches"`). Observed: `mutmut run --
nope.x_f__mutmut_1` → `AssertionError`, exit 1. There is no generate-only command (the CLI is `run`, `results`, `show`,
`apply`, `browse`, `export-cicd-stats`, `badge`, `print-time-estimates`, `tests-for-mutant`).

**Names.** `get_mutant_name`: `src/demo/settings.py`'s `load_settings` → `demo.settings.x_load_settings__mutmut_<n>`;
a method → `demo.settings.xǁSettingsǁcors_origins__mutmut_<n>`; `src/demo/__init__.py`'s `health` →
`demo.x_health__mutmut_<n>` (`.__init__.` is replaced by `.`). So a package's `__init__.py` and its submodules share the
`demo.` prefix, and no fnmatch pattern names one without the other's module whose name begins the same way.

**Decision.** The wrapper runs mutmut's own generation step first — the same calls `_run` makes before stats
(`copy_src_dir`, `copy_also_copy_files`, `setup_source_paths`, `store_lines_covered_by_tests`, `create_mutants`), in the
service's environment through `uv run --no-sync python -c …` — then reads `mutants/<file>.meta`'s `exit_code_by_key`
for each scoped file. An empty one is *no mutant to run* (the demo's `application/ports/read_models.py`, which declares
only types, has `{}`), decided before `mutmut run` and never from its assertion. Otherwise it passes **every key of the
scoped files, exactly**, after `--` (click ends options there; observed with one name), so an `__init__.py` scope is
that file's functions only. The run that follows reuses the generated files: `create_mutants_for_file` sees the mutant
newer than its source and keeps the data (`source_mtime < mutant_mtime`). Probe: generation alone 1.1 s on the demo;
then `mutmut run -- <14 names of settings.py>` 1.6 s, 12 killed and 2 survived, every other file's keys left `None`.

**Why not a pattern per file.** `fnmatch`'s `*` crosses dots, so `demo.x*` catches `demo.xyz.…`; and the empty case
still asserts. **Why not mutmut's internals for the names only** (`mutate_file_contents`): the names would be computed
by a call `mutmut run` does not make, where the generation step is the one it does make and then reuses.

**What this costs a project later:** the step uses functions mutmut does not document as public. The pin is exact, a
pin change sweeps (R6), and the wrapper refuses (exit 2, one line) an environment whose mutmut is not the version it was
written against, naming `slipwai migrate` as what brings a wrapper for a newer pin — ADR 0010.

## R4 — The verdict, from `.meta` (D212, AC-S42-5)

`mutmut/stats.py`, `status_by_exit_code` (a `defaultdict` whose default is `suspicious`): `1`, `3` killed · `0`
survived · `5`, `33` no tests · `2` check was interrupted by user · `None` not checked · `34` skipped · `35` suspicious
· `36`, `24`, `-24`, `152`, `255` timeout · `37` caught by type check · `-11`, `-9` segfault. The `.meta` file is JSON:
`exit_code_by_key`, `hash_by_function_name`, `type_check_error_by_key`, `durations_by_key`,
`estimated_durations_by_key` (`mutation/data.py`, `SourceFileMutationData`).

**Decision.** The wrapper has its own table of 3.8.0's codes: killed passes; no tests is counted on the last line;
survived, timeout, suspicious, segfault, not checked, interrupted, skipped, caught by type check, and any code not in
the table fail, each named with the service, the mutant and its status. `mutmut run`'s exit status is printed and is
never the verdict: the demo run with 114 survivors exited **0** (`full1.log`), and a run whose pytest call failed exited
1 with every key `None` (R7). `export-cicd-stats` is not used: it counts every file (`save_cicd_stats` over
`walk_mutatable_files`).

**Escapes (D212 item 1).** mutmut 3.8.0 reads `# pragma: no mutate` in four forms (`mutation/pragma_handling.py`,
`_parse_pragma_token`): bare (that line's mutations, on a statement or a compound header), `block` (the rest of the
enclosing body, or the whole node on a compound header), and `start` … `end` (the lines between); and the config's
`do_not_mutate_patterns` silences every line a regex matches. A suppressed mutant is never generated, so no status
records it. **Decision (D219's reason, standing):** only the bare per-line form is the per-mutant comment D212 names; a
`block`, `start` or `end` pragma in a judged file, or a non-empty `do_not_mutate_patterns`, fails the run in one line
naming the file and line (or the setting) — they silence mutants nobody looked at. Flagged for the host in plan.md.

## R5 — Clean slate, the cache, and what the run leaves (D212 item 7, AC-S42-9)

A second `mutmut run` on the mini starter reported `0.00 mutations/second`: every result came from the `.meta` files of
the first (`_run`: *"Rerun mutant if it's explicitly mentioned, but otherwise let the result stand"*). mutmut 3.8.0
also keeps `mutants/mutmut-stats.json` and invalidates by function hash, config fingerprint and git change detection
(`collect_or_load_stats`, `_apply_config_change_invalidation`), and on a changed `uv.lock` only *warns*
(`on_dependency_change` default `warn`). **Decision:** the wrapper deletes `<service>/mutants/` before every run and
keeps it after (it is the report). What a run leaves: `mutants/` only — the copy of `src/` and `tests/`, `.meta` and
`.spans` files, `mutmut-stats.json`, `.pytest_cache/` and `__pycache__/` inside it (`find mutants -maxdepth 3`); `git
status` showed `?? apps/service/mutants/` and nothing else. Hence `apps/*/mutants/` in `.gitignore`, an `EXEMPT` row
in `verify-stamp.py`, and `check-imports.py` pruning `mutants` at the root of a Python deployable (its copy holds the
service's whole `src/`, which would be read as a second set of modules).

## R6 — What a change to sweeps (D138 item 3, D216, AC-S42-7)

- `[tool.mutmut]` of a service's `pyproject.toml`, compared as parsed structure (`tomllib`) on both sides.
- The mutmut requirement in the same file (a `mutmut` entry in `[dependency-groups]`, `[project.dependencies]` or
  `[project.optional-dependencies]`), compared as the strings written.
- The service's `uv.lock`: the versions of `mutmut` and of everything `libcst` resolves to (libcst 1.9.0 → `pyyaml`
  6.0.3 off 3.13, `pyyaml-ft` 8.0.0 on 3.13), keyed by name with every version the lock holds. libcst is what parses
  the source and plants the mutants (`mutation/file_mutation.py`, `create_mutations` → `cst.parse_module`), so it is the
  part of mutmut's closure that decides which mutants exist — D222's reason, applied as D222 applied it to Stryker's
  instrumenter; pytest, coverage and textual decide verdicts and display, not the mutant set.
- `scripts/mutmut-mutation.py` — every Python service.
- A side that cannot be parsed, and a Python with no `tomllib` (3.10), count as changed: the service sweeps.

## R7 — What the environment can do to a run (AC-S42-10)

- **Windows.** `mutmut/__main__.py` prints *"To run mutmut on Windows, please use the WSL"* and exits **1** at import.
  `set_start_method("fork")` is called at import too. **Decision:** the wrapper checks `os.fork` (and `sys.platform`)
  first and exits 2 with one line naming WSL.
- **No mutmut in the environment, or the lock disagrees.** The wrapper runs `uv sync --project <svc> --locked --quiet`
  as `scripts/verify` does; a refusal (a manifest the lock does not match) is exit 2 naming `uv lock --project <svc>`;
  then `importlib.metadata.version("mutmut")` in the environment: absent, or not 3.8.0, is exit 2 with one line. No
  `uv` on `PATH` is exit 2.
- **`PYTEST_ADDOPTS="-n 2"`** with `-p no:xdist`: pytest exits 4, mutmut raises `BadTestExecutionCommandsException`,
  exit 1, all 992 keys `None`. **Decision:** the wrapper removes `PYTEST_ADDOPTS` from mutmut's environment and says so
  in one line where it was set; the config's own `pytest_add_cli_args` is how a project adds pytest options.
  `PYTHONPATH` set to the service's absolute `src/` changed nothing (992 mutants, the same counts): mutmut puts
  `mutants/src` first on `sys.path` (`setup_source_paths`), so it is left alone.
- **Concurrency.** Two runs of one service would delete each other's `mutants/`. The wrapper holds an exclusive
  `fcntl.flock` on `<service>/.venv/mutmut-run.lock` for the run (released by the kernel when the process dies; `.venv/`
  is ignored, exempt as rebuilt, pruned by `check-imports`, and the stamp reads only `pyvenv.cfg` there).
- **Noise.** The demo's runs print `Exception ignored in atfork callback … opentelemetry` tracebacks from forked
  workers; they change no status (the same counts in every run).

## R9 — The default starter's own survivors (a finding for the host)

Under D212 the **default** Python starter's `make mutation-full` fails on day one: 114 survivors in
`adapters/driven/checkpoint_store_memory.py` (1), `event_store_memory.py` (22), `adapters/driving/http/app.py` (11),
`application/ports/events.py` (10), `logging_setup.py` (24), `projections.py` (9), `projections_lifespan.py` (14),
`settings.py` (2), `tracing.py` (21). They read as real: `demo.settings.x_load_settings__mutmut_3` turns the `"; "` that
joins validation problems into `"XX; XX"` and no test reads the message. The minimal starter (mini) is green. This is
D217's shape on the TypeScript side; handed back in `plan.md` with options, and nothing in this slice's design depends
on the answer.
