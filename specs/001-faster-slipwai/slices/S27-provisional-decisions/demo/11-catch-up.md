# Catch up: demo27old, 1.6.0.dev0 to 1.6.0.dev0

`slipwai migrate` wrote this before it returned — whether the merge committed or stopped at conflicts — from the catch-up note in each version's entry in the factory's own `CHANGELOG.md`, written by whoever made the change, in the commit that made it. It is what a merge could not do for you.

Work it with `/catch-up`, which reads this file and runs `make verify` against it. This file is git-ignored and disposable: delete it when the work is done, and the changelog stays the record.

## Why the versions crossed could not be listed as such

Because `1.6.0.dev0` and `1.6.0.dev0` are both 1.6.0 — a snapshot of that release, or the release itself — and the changelog keeps one entry per release, so what changed between the two is not told apart. The 1.6.0 entry as it stands today is below; the part of it this project already had cannot be separated from the part it has just taken, so read it as a whole.

## The one entry both versions belong to, 1.6.0

### 1.6.0 — MINOR

`make benchmark` now says how long a slice took from ready to accepted, and where the time went while nobody was working on it, instead of passing off the sum of its stage brackets as the slice's wall time. CI's `verify` job now fetches full history, so a pull request is held in CI to what `make verify` already holds on a developer's machine. `check-imports`, `check-migrations` and `check-codegraph` stop reading what the answer never needed. The gate's independent checks can run at once, and each toolchain syncs once per `make` run. A decision that is easy to take back no longer has to stop a slice. `slipwai` no longer writes an interpreter cache (`__pycache__/`) beside its bundled backing-service assets when it loads their prune script. `adopt --refresh` (experimental: brownfield adoption) no longer rewrites the four files a project owns. `adopt --refresh`, `--confirm` and `--decline` (experimental: brownfield adoption) now refuse to write over an uncommitted change where the project sits in a subdirectory of its git repository. `make model` draws through one browser, and only the diagrams whose source or renderer changed. Every delegated agent now ends its hand-back with one `result-contract` block, and the method keeps it. Every decision can now say how hard it would be to take back. A `/cruise` run reads what it has already read once, not again before every iteration, and a decision entry can now say which slices it binds. On a slice branch, `check-ux-gates` renders only the previews that changed, and the four method-file checks run only when what each declares it reads changed. A generated project's `Makefile` gains `make verify-scoped` and a `lint-`, `typecheck-` and `test-` target for each deployable. A generated project's `make mutation` is priced per change on a slice branch, and `make mutation-full` is the run it was. `check-slice-scope` compares a slice branch with the trunk's own refs, so a branch no longer empties its own check by minting a base. `check-slice-scope` no longer refuses a slice's own code in a repository adopted at its root (`adopt`, experimental), and a slice id with a slug is read whole. `make verify` returns at once on a tree that already passed it. A new Python service's gate runs its tests across cores, and a project can turn that off with one line.

## Then

`make verify`. A gate that is new in one of the versions above fails code that was correct when it was written; the entry that introduced it says what it now wants instead. Never edit a gate to make it pass — it came from the factory, the next migration brings it back, and a locally softened copy is a false green until then.
