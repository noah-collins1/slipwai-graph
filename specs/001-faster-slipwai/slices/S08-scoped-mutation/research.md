# Research: S08-scoped-mutation

Every statement below about a tool's behaviour cites the artefact it was read from. Runs were made on
2026-10-05 against starters generated by this worktree's `./slipwai generate … --no-init --no-install
--skip-checks` under `/tmp/s08/` (GNU Make 4.4.1, Go 1.27.1, the JDK on PATH, Maven 3.9.16 through the
service's `mvnw`, pitest-maven 1.25.9 with pitest-junit5-plugin 1.2.3 as the Spring pom pins them).

## R1. Narrowing PIT to the changed classes needs no pom edit

- **Decision**: a scoped Spring run is the sweep's own command with one more argument,
  `-DtargetClasses=<Foo>,<Foo$*>,…`, run in the service directory. The pom is read, never rewritten, staged or
  copied.
- **Evidence** (run): `./mvnw -B -q test-compile org.pitest:pitest-maven:mutationCoverage
  -DtargetClasses=com.example.spring1.health.HealthStatus` in `apps/service` of a Spring starter mutated
  `HealthStatus` only (1 mutation; the sweep generates 64). The user property wins over the pom's configured
  `<targetClasses>` list for this plugin, which is not Maven's usual precedence for a configured parameter —
  so it is held by a factory test against the pinned plugin (plan, rule 5), not assumed for the next pin.
- **Evidence** (run): `-DtargetClasses=…config.DatabaseUrl,…config.DatabaseUrl$*,…config.DatabaseUrlEnvironmentPostProcessor`
  mutated `DatabaseUrl` only: the pom's `<excludedClasses>` still applies under the override, and so do its
  `<targetTests>` and `<excludedTestClasses>` (`*IT`) — the run examined the same 6 `*Test` classes the sweep did.
- **Evidence** (run): a comma-separated value is split into several patterns (three above, two below).
- **Alternatives considered**: a temporary pom beside the real one (`-f`) — leaves an untracked file in the
  service for the length of the run, needs a `.gitignore` line outside this slice's manifest, and a stopped run
  leaves it behind; a staged copy of the service (Go's precedent) — breaks a project pom that names a parent by
  relative path, and recompiles from nothing; making the pom read a property — a project owns its pom
  (Principle I) and widens `targetClasses` itself, so `migrate` could not carry the change to it.

## R2. PIT's pattern language, for the intersection with the pom

- **Decision**: the scope script reads `<targetClasses>` and `<excludedClasses>` from the `pitest-maven` plugin
  of the service's `pom.xml` and matches each changed class's fully qualified name with PIT's own glob rules: the
  whole name (anchored), `*` any run of characters including `.`, `?` one character, `$` and `.` literal, a
  leading `~` a raw regular expression, `**.` zero or more packages. A class outside `targetClasses`, or inside
  `excludedClasses`, is named *outside PIT's configured targets* and is not passed.
- **Evidence** (source): `org.pitest.util.Glob` in `~/.m2/repository/org/pitest/pitest/1.25.9/pitest-1.25.9.jar`,
  disassembled with `javap -c -p`: the constructor strips a leading `~` and compiles the rest as a regex; else
  `convertGlobToRegex` replaces `**.` first, then maps `$`→`\$`, `*`→`.*`, `?`→`.`, `.`→`\.`, escapes `\ ( ) [ ]`,
  wraps in `^…$`; `matches()` is `Matcher.matches`.
- **Evidence** (run): `-DtargetClasses=…events.TagQuery,…events.TagQuery$*` mutated `TagQuery` (6) and
  `TagQuery$Filter` (9); `-DtargetClasses=…events.Tag` mutated nothing — a bare name is exact, never a prefix,
  which is why D138's `Foo` and `Foo$*` is the pair, never `Foo*`.
- **A pattern the script cannot read** — a `${property}` inside a param, a `~` regex Python cannot compile, a
  pom that does not parse — makes that service's run the sweep, named with the file (fail closed, D138 item 3).

## R3. `failWhenNoMutations` cannot be switched off from the command line

- **Decision**: a scoped Spring run whose classes PIT finds nothing to mutate in (an interface, a record with no
  logic) is recognised by PIT's own message and reported as `no mutant to run — PIT found no code to mutate in
  <classes>`, exit 0 (AC-S08-4: a scoped run never trips `failWhenNoMutations`). Every other non-zero exit is
  the run's failure, unchanged. The sweep keeps `failWhenNoMutations` exactly as the pom has it.
- **Evidence** (run): `-DtargetClasses=…events.EventVisitor` (an interface) exited 1 with
  `failed: No mutations found. This probably means there is an issue with either the supplied classpath or
  filters.`; adding `-DfailWhenNoMutations=false` still exited 1 with the same message — the pom's `true` wins
  for this parameter, unlike `targetClasses`.
- **Evidence** (run): PIT does not rewrite `target/pit-reports/mutations.xml` on that failure (the previous
  run's 15 mutations were still there), so the line says no report was written rather than pointing at one.
- **Alternative considered**: setting the flag through a rewritten pom — rejected with R1's alternatives.

## R4. Go: the scope is passed as files, through the script that already stages the module

- **Decision**: `scripts/go-mutation.py` gains `--file <path within the module>` (repeatable). It skips its own
  `git diff` and feeds the given files through the same `mutable()` and `scope()` it uses for `--since`, so the
  `.gremlins.yaml` exclusions are carried back exactly as today. `--since` stays as published, for
  `mutation-full SINCE=…` and for anyone calling the script directly.
- **Evidence** (source): `assets/languages/go/scripts/go-mutation.py` — `changed()` is `git diff --name-only
  --relative <ref>` plus untracked files; `mutable()` drops the yaml's `exclude-files`; `scope()` builds the
  complement; `--exclude-files` replaces the yaml's list (the docstring, verified against Gremlins 0.6.0 on
  2026-09-21).
- **Why not `--since <merge-base>`**: the set would be computed twice by two readers (the scope script's, D117
  rule 2's import of `check-slice-scope`, and the script's `--relative` diff); one reader is the decision (D138
  item 2: both scoped runs agree on what changed).

## R5. `SINCE` reaches the script through the environment

- **Decision**: the `mutation` recipe does not spell `SINCE`; the script reads `os.environ`. Unset is the
  implicit scope; set and empty is the sweep (AC-S08-10); set is `git diff <ref>`.
- **Evidence** (run, GNU Make 4.4.1): a recipe running `python3 -c "print(os.environ.get('SINCE'))"` printed
  `None` for `make`, `'main'` for `make SINCE=main`, `''` for `make SINCE=`, and `'env'` for `SINCE=env make`.
- **Evidence** (documentation): the GNU Make manual, *Communicating Variables to a Sub-make*: "make exports a
  variable only if it is either defined in the environment initially or set on the command line". Not run under
  make 3.81 (none on this machine): *assumed* there for the empty value, and the factory test runs under the
  machine's make. **D151:** that assumption stands as an assumption, recorded here, until a make 3.81 run proves it.
- **Why**: a ref may hold `'`, `"` or `$` (git's refname rules forbid none of them), and any spelling of
  `$(SINCE)` inside a shell word has to quote it; the environment needs no quoting. Today's Go spelling,
  `$(if $(SINCE),--since $(SINCE))`, cannot tell an empty `SINCE` from none at all.

## R6. The checkout borders and the change set are read from the scripts that already define them

- **Decision**: the scope script loads `verify-scoped.py` beside it and asks its `Ground` and the borders `ci`,
  `head`, `trunk`, `slice_branch`, `base` and `told`, in that order, catching what `reason()` catches; `idle` and
  `forced` are the stamp's and are not asked. The change set is `check-slice-scope.py`'s `changed_files(base)`
  through the same `Ground.scope` (D117 rule 2, D138 item 2), with `base` the merge-base `records.base_of`
  reads for `verify-scoped`, or the commit `SINCE` resolves to. Loaded, never copied, as `verify-scoped.py`
  loads `verify-stamp.py`.
- **Evidence** (source): `assets/toolkit/scripts/verify-scoped.py` lines 60–126 (`Ground`, the borders,
  `BORDERS`, `reason`); `assets/toolkit/scripts/check-slice-scope.py` `changed_files` (`git diff --name-status
  -z --no-renames <base>` plus untracked, so a rename is a deletion and an addition and the new path is the one
  mutated — D138 item 1).
- **Risk, named**: S06 is still converging on these files; the import names are held by this slice's tests, and
  the rebase onto S06's tip re-runs them.

## R7. Nothing S08 adds reaches the scoped gate's record

- **Decision**: `mutation` and `mutation-full` are rules `verify`, `verify-checks` and `ci` do not reach, with no
  variable, `export` or `define` of their own; the recipe spells only `$(MAKE)` and `$(firstword
  $(MAKEFILE_LIST))`, which `verify-scoped`'s own recipe already uses.
- **Evidence** (source): ADR 0005 (`delivery/docs/adr/0005-generated-makefile-rules-fingerprinted.md`) and D133:
  `rules.json` holds rules reachable from `verify`, and every file-origin variable is compared — so a new global
  variable would make every scoped run the full gate. `src/slipwai/project/scoped_targets.py` line 135 spells
  the same two references in `verify-scoped`'s recipe.
- **Evidence** (source): `verify-stamp.py` `EXEMPT` already lists `gremlins.json` and `target/` (where PIT
  writes `pit-reports/`); the Go run stages under `tempfile.mkdtemp()`, outside the project; the scope script
  sets `sys.dont_write_bytecode` before loading anything. So AC-S08-14 needs no new row; the plan holds it with a
  test rather than a row.

## R8. The adopted layout

- **Decision**: the scope script reads `project.json`'s `layout.delivery`; where it is set it prints `mutation:
  this layout has no mutation scope — the recorded command runs` and runs `$(MAKE) -f <makefile> mutation-full`,
  whose recipe is today's, the wrapped applications' recorded commands included (AC-S08-15).
- **Evidence** (source): `src/slipwai/layout.py` (the delivery paths move under `layout.delivery`, so the recipe's
  `scripts/` becomes `<delivery>/scripts/`); `src/slipwai/project/gate.py` `stamped()`; `scoped_targets.adopted_rule`
  (the same shape for `verify-scoped`).

## R9. Production and test files, per backend

From the starters (`assets/languages/*/app`): Go — `*.go` under the service, `*_test.go` a test; Java (both
frameworks) — `src/main/java/**/*.java` production (never `package-info.java` or `module-info.java`),
`src/test/**` a test; TypeScript — `src/**` with a script extension, never `*.d.ts`, `*.test.*` or `*.spec.*`,
production, `tests/**` and `*.test.*`/`*.spec.*` a test; Python — `src/**/*.py` production, `tests/**` a test.
Anything else under a service (a pom, `package.json`, resources, a README) is a non-source file.

## R10. Cost baseline (for AC-S08-19, measured again at the demo)

The Spring starter's sweep (`make mutation`, today's recipe) took 28.5 s wall, 64 mutations, on this machine with
PIT already in `~/.m2`. The scoped runs in R1–R3 each took a fraction of that, dominated by Maven's own start.
The two-service Go figure is the demo's to take.
