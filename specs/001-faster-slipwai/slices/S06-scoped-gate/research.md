## R-2 Per-deployable recipe lines, and which lines are shared

`service_commands()` (`native_commands.py` 71–180) spells each backend's commands with `APP`; `merged()` (183–200)
keeps each distinct line once. Lines naming no service path, read from the table: Python — every gate line
(`./__VERIFY__ --lint-only` etc.); Go — `lint`'s `test -z "$$(gofmt -l $(GO_MODULES))"` and `test`'s
`GO_COVDATA_READY` (`languages/go.py` 53: `go tool covdata percent -i=. >/dev/null 2>&1 || true`); TypeScript —
none in `lint`/`typecheck`/`test` (`npm ci` is `install` only); Java — none (`MAVEN` is `cd APP && ./mvnw -B -q`,
`backends.py` 56). Web apps' lines are appended in `native_commands()` (297–305), not by `service_commands`, hence the
extraction of `web_recipes()`. Go's shared lines run first in their recipes, so a family target as a prerequisite
keeps their order.

## R-3 Names that collide

`SERVICE_NAME` (`src/slipwai/services.py` 47) is `[a-z][a-z0-9-]*[a-z0-9]|[a-z]`, so `integration` and
`integration-billing` are valid deployable names; `test-integration` and `test-integration-<service>` are existing
targets (`makefile.py` 321; scratch `pyshop`: `test-integration: test-integration-service test-integration-billing`).
A `test-<name>` for such a deployable would redefine an existing target's recipe. Underscore is outside
`SERVICE_NAME`, so `lint_python` cannot collide with a unit; `help`'s pattern (`makefile.py` 290) lists only rules
carrying `## `, so units and family targets stay out of `make help`.

## R-5 A sub-make started from Python keeps `-j`

Scratch `/tmp/s06-plan/js`: a recipe `@python3 run.py "$(MAKE)"` whose script runs `make a b`, each target sleeping
one second. Under `make -j2` (4.4.1's default `--jobserver-auth=fifo:…`) the two ran together (1.03 s). Under
`--jobserver-style=pipe` (`--jobserver-auth=3,4`, the only style before 4.4) the child warned *jobserver
unavailable: using -j1* and took 2.04 s; with `subprocess.run(..., close_fds=False)` it took 1.03 s. A recipe line
holding `$(MAKE)` is what makes make hand the descriptors on (GNU Make manual, *How the MAKE Variable Works* —
*assumed* from the manual, consistent with the run).

## R-6 The stamp, and where the baseline goes

`assets/toolkit/scripts/verify-stamp.py`: the stamp is `<git-dir>/slipwai/verify-stamp-<sha256(prefix)[:16]>.json`
(`stamp_directory`, `project_name`, `stamp_path`, 520–532); `begin_full_run` (733–754) removes the stamp and the
pending note before every full run; `record` (841–879) writes only when not `declined()` (`-i`, `-n`, `-t`, `-q`,
`RATCHET_TIGHTEN`), `eligible()` (not CI, not detached, not the trunk, trunk known), the run token matches, and the key
equals the one the run began with; `reuse`'s ratchet path (767–768) returns without `begin_full_run`. Tools are asked
once per run (`machine_tools`, 472–480), stored as `stored_answer` words plus a digest; variables are
`variable_record` bytes (368–371), unset distinct from empty; `VARIABLES` (115–120) and `UNKEYED_VARIABLES` (122).
So a baseline written in `record` right after the stamp, and removed in `begin_full_run` and the ratchet path, is
written only by a green full run on an eligible branch with an unmoved key, and is gone after any full run that did
not pass — with no change to the Makefile's `verify` text (AC-S06-14). `is_gate_script` (483–486): `Makefile` and
everything under `scripts/`.

## R-9 Contracts as the tree has them

`openapi.document_of` puts the document at `<service path>/openapi.json` (`openapi.py` 80–83), inside the service's
path, so *the document or its source* is a change under the service's path. A web app's `api` names its service
(`project.json` `deployables.web.api`, scratch `shop`). A directory under `packages/` with a `package.json` is an npm
package (`build-packages`'s loop; `BIOME_FORMAT`'s comment, `native_commands.py` 224–237); `packages/` is also where
a Go module may live (`check-flags.py`'s `SOURCE_TREES` and its line 111: shared code under `packages/` *still has a
language*), so a `packages/<p>/` without `package.json` is not the npm contract (plan R5 e4). Events: a slice's
`service` (`event-model/check.py` 307), its `reads` (156–162), and its produced events as `frames` of type `evt` that
are not `external` (500–508).

## R-10 How a new toolkit script reaches a project

`toolkit_files_from_assets` copies every file under `assets/toolkit/` unless the profile or a capability excludes it
(`src/slipwai/toolkit.py` 44–76, 156–184), passing each through `spoken_for`, which rewrites `apps/service` and
`apps/web` as whole segments (`ASSET_PATHS`, 82–85) — so the new scripts hold neither literal. Importing a sibling
writes `__pycache__/` unless `sys.dont_write_bytecode` is set (`check-slice-scope.py` 555–557 says why: an untracked
file there would be a change under `scripts/`, which would make every later scoped run the full gate).
